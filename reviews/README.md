# 収益化の週次点検

毎週日曜の朝、クラウドの定期タスク「収益化の週次点検」が、次のことをしてこのフォルダに1本ずつ書く。

1. **数字を見る**：常時接続PCが集めたnoteの週次（`ai_yorimichi_master` の `automation/publisher/state/stats/`、読むだけ）と、Gmailのnote購入メール・ココナラのメールから、今週の実績を出す
2. **動向を調べる**：今の計画（[PLAN.md](../PLAN.md)）の前提が古くなっていないか、より効率のよい方法が出ていないかを、ウェブで調べる。対象の例：note・ココナラ・X・Typefully・Instagram/Threadsの規約や料金の変更、AI活用の小さな受託や有料記事で実際に売れている型、同じ規模（フォロワー数十人）からの立ち上げ方
3. **評価する**：見つけたものを、目標（2027年7月までに約5.7万円）への効き目・編集長の手間（分）・費用・リスクで比べる。根拠のURLを付ける
4. **直す提案を出す**：必要なときだけ。計画の文書は直さず、提案として書く。決めるのは編集長

ファイル名：`YYYY-Www.md`（例 `2026-W44.md`）。このリポジトリのブランチ `claude/review-YYYY-Www` に書いてPRを作る（マージは編集長）。

結果はスマホへ3行以内で届く：「今週の数字・計画の要修正の有無・最優先の一手」。
