# X自動投稿 受け渡し仕様（Muse招待コード定期発信）

このファイルと posts.json / posts.csv を、既存のX自動投稿の仕組みに渡してください。
Threads側はマルローネ（Museエージェント）が担当するので、この仕様の対象はXのみです。

## 1. 目的

Museの招待コード DKR2BF が実際に使われること。単なるコード連投ではなく、体験談・使い方・手順・Q&Aを回して、固定ポストへの導線を作る。

### 方針（2026-11-02 改訂：二番煎じ狙い）

- スタートダッシュで上限まで招待した層は対象外。狙うのは「気になってたけど、まだ始めていない人」
- 煽らない。残り回数や全体の締切など未確認の数字で焦らせない。伝える期限は「参加後48時間以内のコード入力」だけ
- 押すのは始めやすさ: 先行組の実例、失敗しない手順、コピペできる「最初の頼み方」
- 第1週（11/2月〜11/8日）は「はじめる週」シリーズとして posts データ差し替え済み。月=宣言、火=頼み方①メール整理、水=頼み方②調べ物→下書き、木=頼み方③定期チェック、金=手順、土=Q&A、日=まとめ（保存用）
- 詳細は 04_二番煎じ戦略.md

## 2. 固定情報（変数）

- invite_code: DKR2BF
- join_url: https://muse.ai/join
- offer: 参加後48時間以内に設定でコードを利用すると、両方に10億Museトークン
- redeem_rule: アプリは［設定］→［Redeem token］、ウェブは Settings > General > Usage > Redeem invite code
- account_x: @ai_yorimichi_la
- account_threads: @ai_yorimichi
- timezone: Asia/Tokyo（全時刻JST）

## 3. 投稿データ

- posts.json: 設定（config）と投稿配列（posts）。機械可読な正はこちら
- posts.csv: 同内容のCSV版。text内の改行は \n の2文字でエスケープしてあるので、読み込み時に実際の改行へ戻すこと
- 各レコードのフィールド: date, time_jst, platform, slot, pillar, text, char_count
- platform=x のレコードだけを使う（threads行は参考・重複管理用）
- char_count はXの加重カウント（URLは23として計算済み）。全レコード280以内を確認済み

## 4. 頻度とパターン

- 本投稿（slot=main）: 毎日 12:15 JST に1本
- 追加短文（slot=extra）: 金曜と日曜のみ 20:45 JST に1本（データに含まれる4本のみ）
- 期間: 2026-11-02 〜 2026-11-15 の14日分、計 X 18本
- 並び順: date と time_jst の昇順にそのまま投稿。pillar（柱）の順序を崩さない

柱の7日サイクル: 案内 → 体験談 → 使い方 → 手順解説 → Q&A → 体験談 → リマインド

## 5. 14日終了後（15日目以降の継続ルール）

- 同じ pillar のサイクル（7日）を維持し、文面は使い回さない。新規文面はマルローネが週次で供給する（月曜に翌週分を用意）
- 同一文面・酷似文面を30日以内に再投稿しない。投稿済み text のハッシュを保持し、一致したらスキップして報告
- 固定ポスト（2026-11-02の案内）は再投稿しない。リマインド系の投稿から参照するだけにする

## 6. 表記ルール

- ハッシュタグは原則なし。付けても最大2つ、毎回は付けない
- コードと特典の数字はデータの文面どおりに。残り回数など未確認の数字を足さない
- リンクは join_url のみ。他のURLへ差し替えない
- 投稿前に text の改行・コード表記が崩れていないかチェックする

## 7. 停止条件（いずれかで即停止し、所有者へ報告）

- コードが無効・失効したという公式表示、または利用者からの確かな報告
- 同一文面の二重投稿が発生した（その日の残りも停止）
- Xから自動投稿に関する警告・制限通知が出た
- 所有者から停止の指示があった

## 8. 投稿結果の返し方（計測用）

投稿ごとに、次の1行を 03_計測シート.csv と同じ列で返してください。

date, platform, slot, pillar, post_url, impressions, likes, replies, reposts, notes

取得できない指標は空欄でよい。post_url だけは必須（投稿できたことの証跡）。

## 9. Threads側の運用（参考）

- 毎日 20:30 JST に本投稿1本。文面は posts.json の platform=threads 行
- 投稿文は所有者が事前に承認したものだけを使う。週次（月曜9時ごろ）にマルローネが翌週分の下書きと、前週の反応の要約を用意する
- 固定投稿のピン留めとプロフィール編集はThreadsアプリ側の手作業（導線キット参照）
